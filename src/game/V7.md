# ODDWORLD v7: UI, feel and progression (the user's newest instructions; they override V6.md and ART.md where they differ)

V6.md still describes the systems and their APIs (pod, items and containers, logistics, crew, research, cyborg workers).
This file sets how everything LOOKS and FEELS and how the player progresses. Read it, then V6.md for APIs.

## What the user hates (never do these)
- Full-screen 3D scenes as menus (the "R&D station" style), hologram slop, walls of text, generic plain or untextured UI,
  simple block shapes, plain screens, plain line textures, sketchy hand-drawn ink/chalk/doodle looks, AI-slop art.
- UI that does nothing useful (the old top-middle vitals strip and the top-left location plate: remove or fold them in).

## What the user wants
- UI made the way professional game studios do it: a 2D UI (detailed, hand-PAINTED pixel art, like a professional pixel
  artist would paint it: clean clusters, 1 px dark outlines, highlights, shading, material texture), with detailed 3D
  ELEMENTS inside it (models rendered with texture and a BLACK OUTLINE, interactive: they rotate, react, animate).
- Polish and juice everywhere: transitions between every mode and screen, buttons that press and spring, counters that
  roll, panels that slide or unfold, sounds, particles. When an item or building is placed: a little bounce and a dust
  puff scaled by its weight. Every effect feels hand-made and satisfying.
- Very little text: icons, pictures and numbers first.
- Learn from Limbophobia (the user's game; code in src/limbo) and from shipped games.
- A new, better, more detailed pixel font (chosen by the lead; see "Fonts").

## Layout (desktop first)
- MAIN DOCK with 5 big slots, each with a very detailed icon: BUILD, RESEARCH, TROOPS, LAB, SHIP. Clicking one transitions
  into its mode:
  - BUILD: the camera goes top-down into a BLUEPRINT build mode. Buildings are dragged in like a city builder, with locked
    and unlocked builds, move, rotate, the resources needed, click to move or rotate placed buildings.
  - RESEARCH, TROOPS, LAB, SHIP: each opens its own detailed, interactive screen (2D UI with 3D elements, not a 3D room).
- TOOLS: a widget shows the CURRENT TOOL; click to use it; HOLD to open the full ARSENAL; swipe left/right to change tool;
  assign tools to slots; BUILD CUSTOM TOOLS. Tools are useful, interactive and crucial to progress.
- MAP: much better looking, with landmarks, resources and points of interest.
- STORAGE: a better, slightly 3D storage widget that shows TOTAL resources; click to see more (the container grids).
- CLICKING A BUILDING: its info shows as a blueprint sheet, with worker assignment and controls.
- TROOPS: proper RTS human management (select, box-select, control groups, orders, unit cards with health, morale and needs).
- RESOURCES in the world are 3D models with variants and piles (logs, stone, ore, soil, crates), beautiful, not AI slop.
- Item icons must be far more stylised and beautiful (the current ones are "ugly").

## Progression
- You start from ZERO and learn and unlock everything one by one, including the ship's features.
- The skill tree is QUEST + RESOURCE based. Unlocking a function needs enough KNOWLEDGE or enough CLOSENESS with an NPC.
- Every feature should feel important to progression.
- Start: you crash on the planet in a dumb pod; the guide is already there.

## Fonts
- Set by the lead in src/style.css. Use only the families defined there, at their native pixel sizes.

## LIMBOPHOBIA IS THE REFERENCE (the user's own game: /home/user/pukkingdragon123/fictional-octo-train, read-only)
Study its UI code before designing anything: src/ui/pxKit.ts + pxKit.css, pixelkit.ts, hiPixel.ts, icons.ts, iconChip.ts,
hotbar/*, map/surveyMap.ts, inventory.ts, itemPanel.ts, itemTip.ts, floatIcon.*, worldPrompt.*, questTracker.ts,
fonts.css, style.css, src/gfx/bitfont.ts, and its UI sounds in src/assets/sfx/ui_*.mp3 (CC0, credited in
CREDITS-AUDIO.md). Porting its code, art methods and CC0 sounds into ODDWORLD is allowed (same author); credit the sounds.
Its UI rules, which the user wrote and which now apply here too:
- Highly textured, polished, detailed, always in the game's own look. Never a generic smooth 3D render, never low-res
  mush or placeholder-flat.
- Real 3D objects with rich materials (worn metal, glass, enamel, paper, brass), well lit, bright, never murky.
- Interactive and physical: grab, drag, drop, press, pull; things react with motion, sound and physics.
- Minimal text: icons and numbers; no hint lines, sign plates or label spam. Menu buttons are FLOATING ICONS with their
  short name as floating styled text under them. Never put menu icons in boxed keys, tiles or button frames.
- No plain "UI blocks": no flat rectangles of colour holding text or buttons. Every element is a designed object
  (detailed pixel art, a 3D prop, or something in the scene). Choices and prompts float as styled, slightly 3D text.
- No rounded UI, no speech bubbles (dialogue goes to a subtitle strip), no angled red "stamp" effects, no eye icon.
- Recorded CC0 sound effects only.
- Before showing anything, compare its screenshot against this list; if it fails any point, it is not done.

## FONT (lead's choice, as the user asked): Alagard
Alagard (Hewett Tsoi; the user supplied it for Limbophobia and Lerfolese) for ALL text, drawn with a 1 px ink outline
(8-way), crisp at 16 / 32 / 48 px only. Canvas text: port Limbophobia's src/gfx/bitfont.ts. Family 'Alagard' in style.css;
the old family names alias to it.

## Story start (user answers)
- The GUIDE is a STRANDED EXPLORER: a human survivor of an earlier UNAA mission, already on the planet. Closeness with
  them (and other NPCs) unlocks functions.
- The POD is broken and ruined. Clicking it zooms INSIDE the pod, where you build small decor, furniture and necessities
  to raise happiness. Everything else is learned and unlocked one by one.
